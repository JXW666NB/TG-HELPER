## 一、AI Agent 智能优化

### 1.1 核心逻辑重构（`agent.py` +3860 字节）

| 新增/改动 | 说明 |
|-----------|------|
| `_original_goal` 目标追踪 | 每次构建消息时注入目标提醒，防止 AI 在长对话中遗忘原始需求 |
| `_compress_context()` | 对工具调用结果智能截断（42000 字符阈值），防止上下文爆炸 |
| `action_history` 动作轨迹 | 每次工具调用记录 `(步骤N: action → result)`，AI 感知自己已做了什么 |
| `max_iterations` 优化 | 从 50 降至 30，减少无效循环 |
| 上下文预警 | 总上下文超过 500000 字符时发出警告 |

### 1.2 工具参数名自动纠正

- 新增 `_normalize_action_input()` + `_PARAM_ALIAS_MAP` 映射表
- 覆盖 **10 类、40+ 个常见错误别名**（`file_path`→`filepath`，`dir`→`directory`，`cmd`→`command` 等）
- 系统提示词新增"常用工具参数名速查"板块，从源头减少 AI 猜错
- **debug 模式下自动打印 `[参数纠正]` 日志**

### 1.3 工具提示词截断修复（关键 BUG）

- **问题**：AI 读取 `tool_prompts/` 文件后，结果写入短期记忆时被 `[:300]` 截断
- **后果**：AI "从聊天记录回忆"时只能看到前 3 行工具，后续工具全部丢失
- **修复**：截断阈值从 300/5000 统一提升至 **42000 字符**（适配 DeepSeek V4 1M 上下文）
- 短期记忆记录和上下文压缩均同步提升

### 1.4 `max_tokens` 提升

- `config.py` 中 `max_tokens` 从 2000 → **8000**
- 适配网页 HTML 提取、长文件读取等大输出场景，避免 JSON 截断导致解析失败

## 六、全新模块：内存优化系统

### 6.1 新增文件

| 文件 | 说明 |
|------|------|
| `memory_optimizer.py` | 核心模块：进程管理 + 内存清理 + 显存清理 + 安全白名单 |
| `tool_prompts/内存优化（进程管理、内存清理、显存清理）.txt` | AI 工具提示词 |

### 6.2 功能矩阵

| 工具函数 | 功能 | AI 可调用 |
|----------|------|-----------|
| `list_processes(top_n=30)` | 列出进程，按内存占用排序，标注 🛡️ 受保护进程 | ✅ |
| `kill_process_by_name(name)` | 按名结束进程（白名单保护） | ✅ |
| `kill_process_by_pid(pid)` | 按 PID 结束进程（白名单保护） | ✅ |
| `optimize_memory()` | Python GC + 释放工作集 + Windows EmptyWorkingSet | ✅ |
| `optimize_vram()` | CUDA 显存释放 + ONNX Runtime 清理 | ✅ |
| `full_optimize()` | 完整内存 + 显存优化 | ✅ |

### 6.3 安全机制

| 层级 | 保护 |
|------|------|
| **系统白名单** | `explorer.exe`、`dwm.exe`、`svchost.exe`、`lsass.exe`、`winlogon.exe`、`csrss.exe` 等 18+ 个关键进程 |
| **AI 自身保护** | 自动获取当前进程及其所有父进程 PID，加入不可关闭列表 |
| **PID 保护** | PID 0 和 PID 4 不可操作 |
| **AI 提示词约束** | 提示词末尾明确"严禁关闭系统进程"，白名单透明标注 |

### 6.4 GUI 集成

- 调试栏重命名为 **"通用设置"**
- 新增"内存优化"区域，4 个按钮（查看进程、内存优化、显存优化、完整优化）
- 绿色高亮完整优化按钮，灰字说明"非破坏性操作"
- **所有操作在后台线程执行，不阻塞 GUI**

### 6.5 自动化

- **启动时**：延迟 2 秒（界面就绪后）自动执行 `full_optimize()`
- **关闭时**：`on_closing()` 执行 shutdown 前自动优化
